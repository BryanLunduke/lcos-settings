# LCOS Command Center review (2026-11)

Reviewed tree: `dd585e4a30ed4b967f8286628c49b14729f2082d` (`master` at the merge of Command Center 1.1~dev).
This is a report only. No product code was changed.

The program is a gtkmm 3 settings window that writes the xfconf channels used by XFCE 4.20, plus a pkexec helper for timezone, clock, chrony, locales, accounts, avatars, and LightDM autologin. Editor decisions that this review treats as intentional, and does not flag as gaps: no Workspaces page, no separate Security tab (the lock checkbox lives on Power → System), Desktop is Background / Icons / Menus only, and the GNOME and KDE startup checkboxes stay hidden unless those stacks are installed.

## How this was checked

- `meson test`: `logic` and `session` both passed.
- `cppcheck --enable=warning,performance,portability` on `src/` reported one style hit (an unused pair of assignments in `conf_with_autologin`). No memory or bounds findings.
- ASan/UBSan build (`-Db_sanitize=address,undefined`). Under Xvfb, with a session bus and `xfconfd`, the sanitizer build walked every page through `LCOS_SETTINGS_DUMP_PAGES` and exited 0. LeakSanitizer reported shutdown residue in fontconfig, GTK, and GDBus (about 294 KB, stacks in those libraries). It did not report a use-after-free. PulseAudio was not running, so the libpulse operation leak in F11 was not exercised by that run.
- The privileged helper was run as root against a disposable account. A symlink planted at `~/.face.lcos-tmp` caused the helper to create a file in a root-owned directory and `chown` it to the unprivileged user. A separate `chown` of a symlink changed the owner of a root-owned target.
- A copy of `PrivSession::run`'s spawn/wait loop treated `/bin/false` and `exit 1` as success on all 300 trials (`waitpid` returned -1, status stayed 0). The same shape of parent, reading only stderr, deadlocked until `SIGALRM` when the child wrote 256 KiB to stdout.
- Screenshots in this directory were taken with `GDK_BACKEND=x11` on Xvfb (`Adwaita` and `Adwaita:dark`).

## Fix these first

1. **F1.** Stop treating a reaped pkexec child as success. Helper failures and dismissed auth dialogs are currently reported as success.
2. **F2.** Stop following symlinks when writing and chowning `~/.face`. A standard user can gain a root-created file of their choosing when an administrator sets that account's picture.
3. **F3.** Preserve `root:shadow` and mode `0640` when rewriting `/etc/shadow`. Cancel after a password, name, or account-type change can make `unix_chkpwd` unable to read the file.
4. **F4.** Read the helper's stdout while it runs, and do not run `locale-gen` on the GTK thread. A noisy `locale-gen` fills the pipe and the window never returns.
5. **F5.** Store `/Xft/DPI` as `dpi * 1024`, which is what `xfsettingsd` reads. The spin shows and writes the raw integer.
6. **F6.** Give Date & Time, Language, Users, and Startup separate undo, and do not mark the privileged session finished until the window is actually closing. Apply currently makes every later privileged change fail.
7. **F7.** Record the previous clock, and roll back `locale.gen`, a half-created account, and a moved home directory when the helper fails or the user cancels.
8. **F8.** Do not disable every CRTC before the new layout is known to be accepted, and apply scale with the same transform and framebuffer size XFCE 4.20 uses.
9. **F9.** Merge autostart keys the way `xfce_rc` does, and do not write `Hidden=true` when turning off an OnlyShowIn entry that is not XFCE.
10. **F10.** Stop painting the sidebar and the subtitle with colors that ignore the dark theme. Unselected sidebar text measured at 1.2:1.

## 1. User-facing bugs

### F5. High. Custom DPI is stored and shown in the wrong unit

`src/pages/appearance_page.cpp:172`, `src/pages/appearance_page.cpp:183`, `src/pages/appearance_page.cpp:278`

XFCE stores `/Xft/DPI` in 1024ths of a point (96 DPI is `98304`) and keeps the human number in `/Xfce/LastCustomDPI`. This page reads `/Xft/DPI` straight into a spin whose range is 50–500, so an existing value of `98304` is clamped to 500 and displayed as 500. Enabling custom DPI or moving the spin writes that small integer back to `/Xft/DPI`. `xfsettingsd` then treats 96 as about 0.09 DPI.

**Reproduce:** Set `/Xft/DPI` to `98304` with `xfconf-query`, open Appearance, and read the DPI spin. Turn Custom DPI on and apply. Read `/Xft/DPI` again.

**Fix:** On load, show `dpi / 1024` when the stored value is greater than 500. On write, set `/Xft/DPI` to `spin * 1024` and `/Xfce/LastCustomDPI` to the spin value.

### F7. High. Cancel does not restore the clock, a generated locale, or a half-finished account change

`src/privileged/lcos-settings-priv.cpp:319`, `src/privileged/lcos-settings-priv.cpp:447`, `src/privileged/lcos-settings-priv.cpp:493`, `src/pages/datetime_page.cpp:28`

The Date & Time summary says administrator changes are undone by Cancel. `set-time` never snapshots the previous clock, and `revert_token` has no time case. `set-locale` rewrites `/etc/locale.gen` and runs `locale-gen` before it snapshots `/etc/default/locale`. Revert restores only the default file. The page text admits the generated locale stays, but a failed `locale-gen` still leaves `locale.gen` enabled. `add-user` runs `useradd` and `chpasswd` before it records `added.<name>`. If `chpasswd` or the sudo `usermod` fails, the helper exits 1 and nothing marks the account for deletion. `remove-user` renames `/home/<name>` into `/run/lcos-settings/<token>/` before `userdel`. If `userdel` then fails, the home directory is already gone from `/home` and, because the helper exited 1, a client that did honor exit status would not revert it. On a normal LCOS install `/home` and `/run` are different filesystems, so `rename` fails with `EXDEV`, the home stays put, and OK leaves an orphan home directory. The confirm dialog says the files are restored on Cancel, which is only true when that rename succeeded.

**Reproduce:** Turn chrony off, set the clock, press Cancel, and compare `date`. For accounts, point the helper at a `chpasswd` that fails after `useradd` (or fill the filesystem) and see the new account remain with no undo file.

**Fix:** Snapshot the current epoch before `date -s`. Snapshot `/etc/locale.gen` before editing it, and restore it if `locale-gen` fails or the user cancels. Record `added.<name>` immediately after `useradd` and delete the account if a later step fails. Copy the home directory only when source and undo directory are the same filesystem; otherwise leave it in place and say so. Do not `userdel` until the snapshot is durable.

### F8. High. Applying a display layout can blank every output, and scale uses the wrong size

`src/backends/xrandr_backend.cpp:353`, `src/backends/xrandr_backend.cpp:370`, `src/logic/display_layout.cpp:64`, `src/pages/display_page.cpp:774`

`apply()` grabs the server, disables every CRTC, then programs the new modes. If a later `XRRSetCrtcConfig` fails, the function returns an error and `commit_pending` shows a dialog and returns. It does not put `confirmed_` back, so the desktop can stay dark. Scale makes this worse. The screen size and positions use `mode * scale` (`footprint_width`), while the CRTC is still programmed with the monitor's native mode and a transform whose diagonal is `scale` rather than `1/scale`. RandR's transform maps framebuffer pixels onto the output. A diagonal of 2 and a framebuffer of `mode * 2` do not describe the same layout XFCE 4.20 applies.

Hotplug is also missed. `load_hardware()` runs from the constructor only (`src/pages/display_page.cpp:303`). `on_page_shown` repaints. A monitor connected while the window is open never appears.

**Reproduce:** On a machine with two outputs, request a mode the second output does not have and press Apply. For scale, set Scale to 2 on a 1920x1080 panel and compare the resulting `xrandr --query` with xfce4-display-settings.

**Fix:** Build the full CRTC plan first. Program the new screen size and CRTCs without a prior global disable, or restore the saved CRTC config when any status is not `Success`. Match XFCE's scale: framebuffer size `mode / scale`, transform diagonal `1/scale`, and skip the transform when scale is 1 (the Xvfb comment can stay). Subscribe to `RRScreenChangeNotify` and reload.

### F9. High. Startup autostart does not round-trip XFCE's desktop files

`src/logic/system_model.cpp:365`, `src/pages/startup_page.cpp:300`

`merge_autostart` uses the user file *instead of* the system file. XFCE's `xfce_rc_config_open` overlays the user file on the system file, so a user override that contains only

```
[Desktop Entry]
Hidden=true
```

still has `Type=Application` and `Exec` from `/etc/xdg/autostart`. Here, `Type` is missing, the row is dropped, and the user cannot turn the application back on.

The toggle also does not match `xfae_model_toggle` in xfce4-session 4.20 `settings/xfae-model.c`. For an entry whose `OnlyShowIn` does not include XFCE, XFCE flips only `X-XFCE-Autostart-Override` (and clears `Hidden` if it was set). This page always writes both `Hidden` and `X-XFCE-Autostart-Override` from the current checkbox (`startup_page.cpp:304`). Turning such an entry off writes `Hidden=true`, which hides it from every desktop, not only XFCE.

`TryExec` is not consulted. xfce4-session's launcher (`xfsm-global.c` in 4.20) skips a file whose `TryExec` is missing. Those rows still show as enabled here. `RunHook` is parsed and written as 0 for new rows, but the list has no trigger column, so a logout hook looks like a login item.

`X-GNOME-Autostart-enabled` is not read. That matches XFCE 4.20: neither `xfae-model.c` nor `xfsm-global.c` consults it. Do not start honoring it unless the session launcher does too, or the checkbox and the session will disagree. See F23.

**Reproduce:** Put `Hidden=true` alone in `~/.config/autostart/some-system-id.desktop` and open Startup. The system entry disappears. Copy an `OnlyShowIn=GNOME;` file into `/etc/xdg/autostart`, turn it off in this window, and see `Hidden=true` in the user file.

**Fix:** Parse system and user files as one key set, with user keys winning. When the user file has no `Type`, keep the system `Type`, `Exec`, `Name`, and `TryExec`. For `show_in_xfce` entries, write only `Hidden`. For the others, write only `X-XFCE-Autostart-Override`, and clear `Hidden` when enabling. Skip rows whose `TryExec` cannot be executed. Show `RunHook` if it is not login.

### F11. High. Sound changes cannot be cancelled, and per-application sliders are destroyed while dragging

`src/pages/sound_page.cpp:247`, `src/pages/sound_page.cpp:334`, `src/backends/pulse_client.cpp:281`

Pulse volumes are applied on every `value-changed` and there is no snapshot, so Cancel leaves them. The status line says PulseAudio keeps them, which contradicts the window summary that Cancel puts the visit back. The per-application rows are rebuilt on every `changed` signal (`build_apps` removes the old widgets). A sink-input event arrives as soon as `set_input_volume` runs, `refresh` runs, and the scale the user is dragging is destroyed. Output and input scales set `dragging_` to skip that refresh. The application scales do not.

Every `pa_context_get_*` and `pa_context_set_*` return a `pa_operation*` that is never `pa_operation_unref`'d (`pulse_client.cpp:281` and each setter). With a server running, a volume drag leaks one operation per event, and each refresh leaks five more. If connect fails, `on_failed` leaves the context in place, so a later PulseAudio start is never retried (`pulse_client.cpp:218`).

**Reproduce:** Play audio, drag an application slider, and watch it jump back to the last event. Press Cancel and check the sink volume in `pavucontrol`. Run under LSan with PulseAudio up and move the output slider.

**Fix:** Remember volumes at connect time and restore them from `revert_page`. Debounce slider events and do not rebuild a row whose scale is pressed. Unref every operation. On context failure, drop the context so `connect()` can try again, and disable the scales while `state_.ready` is false.

### F15. Medium. Automatic time and the panel clock disagree with the system

`src/pages/datetime_page.cpp:204`, `src/logic/system_model.cpp:263`, `src/privileged/lcos-settings-priv.cpp:245`

Chrony is "on" only when `/etc/rc2.d` contains an `S*chrony` link. A machine that starts chrony from rc3, rc4, or rc5, or that has chrony running without a link, shows the box unchecked and will accept a manual `date -s` while chronyd is running. The helper uses the same rc2 test.

The 12/24-hour control only appears when exactly one panel clock plugin exists. A custom format of `%T` or `%H:%M:%S` is classified as 24-hour. Choosing 24-hour again writes `%R`, which drops seconds. Choosing 12-hour writes `%I:%M %p`.

**Reproduce:** Enable chrony only in rc3 and open Date & Time. Set the panel clock to `%T`, select 24-hour, then 12-hour, then 24-hour, and read `digital-time-format`.

**Fix:** Treat chrony as on when any rc2–rc5 start link exists or `/etc/init.d/chrony status` says it is running. Remember a custom format and only rewrite it when the user actually switches between 12- and 24-hour. If several clocks exist, edit all of them or name which one is shown.

### F16. Medium. Saved sessions are not the sessions XFCE stores

`src/pages/startup_page.cpp:230`, `src/pages/startup_page.cpp:264`

xfce4-session 4.20 stores every saved session as a group in one key file, `~/.cache/sessions/xfce4-session-<display>` (`settings_list_sessions_get_filename` in `libxfsm/xfsm-util.c`). This page lists directory entries whose names start with `xfce4-session-` and Clear unlinks those files. The user sees the display name, not "session name" and "last accessed", and cannot delete one saved session.

**Reproduce:** Save two sessions from the XFCE logout dialog. Open Startup → Session. One file name is listed. Clear removes the whole file.

**Fix:** Open that key file, list `Session: ` groups, and delete one group (then write the file back, which upstream's own delete button currently forgets to do).

### F18. Medium. Automatic login is edited as if it belonged to the selected user

`src/pages/users_page.cpp:146`, `src/pages/users_page.cpp:450`

The combo labeled "Log in automatically" lists every account and sits inside the "Selected account" frame. It is a single system setting. Changing the selected row reloads the same global value. Choosing a name calls `set-autologin` immediately, with no confirm. `valid_username` rejects `root` and `nobody`, but `set-autologin` accepts any other name that `getpwnam` finds, including `sync`, `daemon`, and `www-data` (`lcos-settings-priv.cpp:607`). Other account actions go through `account_or_fail`, which requires uid 1000–65533.

**Reproduce:** Select a standard user, then choose a different name in "Log in automatically". The drop-in at `/etc/lightdm/lightdm.conf.d/60-lcos-settings.conf` changes even though the account type did not. Pass `sync` to `set-autologin` if that account exists.

**Fix:** Make it a checkbox on the selected account ("Log this account in automatically") or move the combo out of the frame. Confirm before writing. Require uid ≥ 1000 and a real shell.

### F19. Medium. Default applications replace the whole added-association list

`src/pages/software_page.cpp:188`, `src/pages/software_page.cpp:345`, `src/pages/software_page.cpp:455`

Choosing a helper or a default writes one desktop id into `Added Associations` and drops any other ids that were there. The Others tab builds a row for every MIME type advertised by every application desktop file, including types with no default. At 1000×550 that list is a long run of `application/pkcs*` rows (see `window-1000x550.png`). `save_files` ignores a failed write and the page never says so. Cancel does restore the original files, which is the right shape.

**Reproduce:** Put two ids in `Added Associations` for `text/html`, pick a browser, and read the file back.

**Fix:** Prepend the chosen id and keep the previous list. Show types that already have a default, plus types of installed apps the user has filtered, grouped the way xfce4-mime-settings does. Surface `file_set_contents` errors.

### F20. Medium. Removable-media commands are written on each keystroke, with no placeholder help

`src/pages/media_page.cpp:42`

The property names (`/autoburn/data-cd-command`, `/autoplay-audio-cds/command`, and the rest) match thunar-volman. The entries do not document the `%d` / `%h` placeholders thunar-volman substitutes, and there is no application picker. An incomplete command is stored as soon as the user types, so a visit that is cancelled is fine (xfconf revert covers it) but a crash mid-word leaves a broken command. Empty commands with the checkbox on are accepted.

**Fix:** Write the command when the entry loses focus. Show the placeholders next to the entry and refuse to enable a blank command.

## 2. Error handling

### F1. Critical. pkexec's exit code is discarded, so failures look like success

`src/backends/priv_client.cpp:75`, `src/backends/priv_client.cpp:102`, `src/backends/priv_client.cpp:111`

`g_spawn_async_with_pipes` is called without `G_SPAWN_DO_NOT_REAP_CHILD`. GLib reaps the child. The code then `waitpid`s. On this system that `waitpid` returned -1 for 300 of 300 runs, left `status` at 0, and the same test treated both `/bin/false` and `sh -c 'echo helper-failed >&2; exit 1'` as success. Stderr was captured and then ignored, because the success branch returns before the error string is used. `dirty_` is set on that false success.

So a dismissed pkexec dialog (pkexec exits 126 or 127), a helper `fail()`, and a missing binary all come back as `ok == true`. Date & Time leaves the new timezone selected (`apply_zone` reloads only on failure). Language does not restore the combos. Users does not show the helper's message. Cancel may then try to revert a change that never happened, or OK may drop an undo directory for a change that only partly happened.

**Reproduce:** Build the spawn loop from `PrivSession::run` and point it at `/bin/false`. Or set `LCOS_PRIV_HELPER` to a script that prints `refused` on stderr and exits 1, change the timezone, and watch the error dialog not appear.

**Fix:** Pass `G_SPAWN_DO_NOT_REAP_CHILD`, use `g_child_watch_add` or `g_spawn_sync`, and treat `waitpid < 0` as failure. Keep the stderr text. Prefer not to block the main loop (F4).

### F4. High. locale-gen can deadlock the window, and Cancel cannot interrupt it

`src/backends/priv_client.cpp:102`, `src/privileged/lcos-settings-priv.cpp:449`, `src/pages/language_page.cpp:240`

The client reads stderr until EOF and never reads stdout. The helper's children inherit that stdout pipe. `locale-gen` writes much more than a 64 KiB pipe buffer. The child blocks on `write(1)`, the helper blocks in `waitpid`, and the client blocks in `read(2)`. A stand-in child that wrote 256 KiB to stdout and then a line to stderr never delivered that line; the parent sat until `SIGALRM`.

Even when the pipe does not fill, `LanguagePage::apply` calls `session_.run` on the GTK thread after a single `process_updates`. The spinner is painted once and the window ignores Cancel, close, and keyboard input until `locale-gen` finishes. The note on the page cannot be acted on during the run.

**Reproduce:** Select a locale that is supported but not generated. While `locale-gen` runs, try to press Cancel. To force the deadlock, substitute a `locale-gen` that prints a few hundred kilobytes of progress to stdout.

**Fix:** Drain stdout and stderr together (`poll`, or `G_SPAWN_STDOUT_TO_DEV_NULL` for commands whose output is irrelevant). Run the helper with `g_subprocess` on the main loop so Cancel can kill the child. If the child is killed, restore `locale.gen` from the snapshot in F7.

### F6. High. Apply ends the privileged session, and Cancel hides revert failures

`src/main_window.cpp:174`, `src/main_window.cpp:252`, `src/backends/priv_client.cpp:54`, `src/backends/priv_client.cpp:132`, `src/backends/priv_client.cpp:144`

One `PrivSession` is shared by Date & Time, Language, Users, and Startup. Each reports `has_pending()` from `session_.dirty()`. Apply calls `commit_pending()` on every pending page and ignores the bool Display uses to say "the user rejected the layout". The first privileged page's `commit()` deletes the undo directory and sets `finished_`. `run()` then refuses every later privileged action with "This change can no longer be made in this visit." The window stays open, so the user cannot change the clock, add a user, or generate a locale until they quit. `commit()` also turns a failed `rm` into success (`return result.ok ? result : PrivResult{true, {}}`).

Cancel calls `revert_page()` on every page. The first one runs `revert()` and sets `finished_` even when pkexec fails. The result is discarded (`DateTimePage::revert_page` returns void). The window hides. Combined with F1, a failed revert can look like success and the undo directory is forgotten while the change remains.

OK does call `commit_pending` for dirty pages before hiding, so a normal OK keeps the changes. That part matches the header comment. Apply should not share that path until the user is done.

**Reproduce:** Change the timezone, press Apply, then try to change it again. Separately, change the timezone, press Cancel, and dismiss the pkexec dialog. The window closes and `/etc/timezone` stays on the new zone.

**Fix:** Commit the privileged session only from `close_keep`, once, and show an error if it fails. Do not set `finished_` until that commit or a successful revert. If revert fails, keep the window open and show the helper text. Let Display's `false` return stop Apply.

### F14. Medium. UPower that starts late never appears

`src/backends/upower_client.cpp:178`, `src/backends/upower_client.cpp:188`

`start()` builds a manager proxy with `DO_NOT_AUTO_START`. If the name has no owner, it sets "UPower is not running." and returns while keeping the proxy. The next `start()` returns immediately. DeviceAdded is never subscribed, so plugging in a battery or starting UPower later leaves the Devices tab on the empty message. The unused proxy is held for the life of the window. `EnumerateDevices` uses the object-path type correctly on the second read; the first `g_variant_get_string` is redundant but harmless on GLib 2.80, which accepts object paths.

**Reproduce:** Open Power → Devices with UPower stopped, then start UPower. The empty state stays.

**Fix:** If there is no name owner, unref the proxy and set it back to null. Watch `NameOwnerChanged`, or call `start()` again from `on_page_shown`.

### F26. Low. Several file writes fail silently

`src/pages/startup_page.cpp:31`, `src/pages/software_page.cpp:43`, `src/pages/language_page.cpp:49`

`write_text` in Startup does not check the stream. `SoftwarePage::save_files` ignores a false return. `locale -a` is spawned with `g_spawn_command_line_sync` and a failed spawn becomes an empty list, so every supported locale is offered as "not generated" and the next choice runs `locale-gen` again. xfconf writes return false and most pages ignore that, so a missing `xfconfd` shows the banner in the main window (`main_window.cpp:160`) but a later toggle still looks like it stuck.

**Fix:** Check stream and xfconf return values and put the message in the existing status label. If `locale -a` fails, say so instead of marking every locale missing.

## 3. Memory and resource leaks

### F11 (also listed under user-facing bugs)

The libpulse operation leak is the one that will grow in a normal session. The ASan page walk did not attribute a leak to `pa_context_*` because no PulseAudio daemon was running.

### F25. Low. The clock timeout is not tied to the page lifetime

`src/pages/datetime_page.cpp:185`, `src/pages/datetime_page.hpp:70`

`clock_timer_` is a `sigc::connection` whose destructor does not disconnect. The callback captures `this`. The ASan run exited with the window and did not use the page after free, because the main loop stopped. A caller that hides the window and keeps running (the dump path deletes the window on idle, then the application quits) is safe only for that reason. `DisplayPage::on_page_shown` and the constructor idle in `MainWindow` have the same unbound lambdas (`display_page.cpp:527`, `main_window.cpp:196`).

**Fix:** Disconnect `clock_timer_` in a destructor, or bind the slot to the widget with `sigc::mem_fun`. Track the idle and remove it in `on_unmap`.

No GObject or GVariant leak was found in `read_device`: every cached property is unref'd. `XfconfStore::list` destroys the hash table it gets. `XRRGetOutputInfo` / `XRRGetCrtcInfo` paths free what they allocate, including the early returns in `apply()`. Identify popups are deleted from a three-second timeout (`display_page.cpp:966`).

## 4. Security of the privileged helper

### F2. Critical. Setting an account picture follows symlinks and hands the target to that user

`src/privileged/lcos-settings-priv.cpp:161`, `src/privileged/lcos-settings-priv.cpp:582`

`write_file` opens `path + ".lcos-tmp"` with `O_WRONLY|O_CREAT|O_TRUNC` (confirmed with strace), `chmod`s it, and `rename`s it onto `~/.face`. `ofstream` and `chmod` follow symlinks. `action_avatar` then `chown`s `~/.face`, and `chown` follows symlinks too.

Reproduced as root against a disposable uid whose home contained `.face.lcos-tmp` → `/usr/local/lcos-review/secret`:

- The helper exited 0.
- It created `/usr/local/lcos-review/secret` (a root-owned directory) and wrote the PNG bytes (`89 50 4e 47…`, 69 bytes).
- `~/.face` was the symlink, and the secret file's owner became the unprivileged account.

`fs.protected_regular=2` blocked the same trick when the target lived in sticky `/tmp` and was owned by someone else (`EACCES`). It does not protect `/etc`, `/usr/local`, or `/home`. After the `chown`, the account owner can replace the PNG with any content. Pointing the link at a new path under `/etc/cron.d` or at an existing file such as `/etc/shadow` is the same open. A second check, `chown` of a symlink to a root-owned file, changed that file's owner to the user.

The source image is checked with `realpath` and a PNG/JPEG magic test, and `..` is rejected. That does not constrain the destination. `remember_file` also reads `~/.face` through a symlink, so a link to `/etc/shadow` copies the shadow file into the root-only undo directory before the overwrite.

**Reproduce:** As the target user, `ln -s /usr/local/somewhere/newfile ~/.face.lcos-tmp`. As root, run `lcos-settings-priv <32 hex> set-avatar <user> <png>`. `ls -l` the target.

**Fix:** `open(dest, O_NOFOLLOW|O_CREAT|O_EXCL)` for the temporary file in a root-owned directory (for example `/run/lcos-settings`), `fchown`/`fchmod` the fd, and `rename` over the destination only after `lstat` shows it is absent or a regular file. Use `lchown` or `fchown` the fd. Refuse if `lstat(~/.face)` is a symlink. Do not read a symlink into the undo snapshot; `unlink` it.

### F3. Critical. Restoring a password rewrites `/etc/shadow` as `root:root`

`src/privileged/lcos-settings-priv.cpp:161`, `src/privileged/lcos-settings-priv.cpp:626`, `src/privileged/lcos-settings-priv.cpp:662`

`remember_account` stores `name:hash` for password, account type, and real-name changes. Revert calls `restore_shadow_password`, which rewrites the whole of `/etc/shadow` through `write_file`. That creates a new inode, `chmod`s it `0640`, and leaves the owner as `root:root` because nothing `chown`s it to `root:shadow`.

On this machine `/etc/shadow` is `root:shadow` mode `0640`, and `/usr/sbin/unix_chkpwd` is setgid `shadow`. After Cancel, the group can no longer read the file, and local password checks fail until someone restores the group. The rewrite also does not take `lckpwdf()`, so a concurrent `passwd` can be lost. The field splice itself is correct for a `name:hash` snapshot with no extra colon in the hash.

**Reproduce:** Change a real name (that snapshots shadow), press Cancel, and run `ls -l /etc/shadow`. This was not executed here because a buggy rewrite would lock the machine out; the `write_file` path is the same one observed creating a `root`-created file in F2.

**Fix:** Edit the password field in place under `lckpwdf`, or `fchown` the replacement to `root:shadow` and `fchmod` `0640` before `rename`. Prefer `chpasswd -e` with the saved hash over rewriting the file by hand.

### F12. Medium. One polkit action covers every privileged operation, and the keep flag caches it

`data/org.lunduke.lcos-settings.policy:8`

`org.lunduke.lcos-settings.manage` is the only action. `allow_active` is `auth_admin_keep`, so after one prompt the same session can, until the polkit timeout, set autologin, change any local password (`set-password` mode `other` does not ask for the target's current password), delete a user, or set the clock. `allow_any` and `allow_inactive` are `auth_admin`, so a subject that is not the active local session can still authenticate and run the helper. The `exec.path` annotation correctly pins `/usr/libexec/lcos-settings-priv`. Arguments are not pinned by polkit; the helper's `argc` checks are what limit the action, and those checks are a single string compare.

Passwords are not placed on the command line. They are written to the helper stdin and then to `chpasswd`. `valid_password` rejects empty, longer than 128 bytes, newline, and NUL, and colons are allowed, which `chpasswd`'s `user:password` format accepts. The bytes are not wiped after use. The undo token is in the pkexec argv, so it is visible to other local users in `ps`, but they still need admin auth to use it.

`LCOS_PRIV_HELPER` lets the client exec a different path. pkexec will refuse it when the policy path does not match, so this is not an escalation. A script placed there is still what the UI will believe (and, with F1, the UI believes it even when pkexec refuses).

**Fix:** Split actions: `set-time`, `set-locale`, `manage-users`, `set-autologin`. Use `auth_admin` without `keep` for user deletion, password changes, and autologin. Set `allow_any` to `no`. Keep `exec.path`. Document that `other` password changes are an admin reset.

### F13. Medium. Account checks are uid-range checks, not "this user is in /etc/passwd"

`src/privileged/lcos-settings-priv.cpp:192`, `src/logic/system_model.cpp:91`

`account_or_fail` accepts any `getpwnam` result with uid 1000–65533. An NSS user in that range (LDAP, if it were enabled later) can be passed to `userdel`, `chpasswd`, and `chfn`. `valid_username` is a reasonable local pattern (`[a-z_][a-z0-9_-]{0,31}`, not `root` or `nobody`) and it does block `:` and newlines in the passwd and LightDM lines. `valid_real_name` blocks `:`, `,`, `=`, and controls, so GECOS injection through `useradd -c` / `chfn -f` is closed. `valid_timezone_name` requires a slash and rejects `..`; `realpath` must stay under `/usr/share/zoneinfo`. `valid_undo_token` is 32 hex digits, so `rm -rf /run/lcos-settings/<token>` cannot escape that directory. `valid_locale_name` is limited to alphanumerics plus `_ . @ -`, and `enable_locale_in_gen` only writes `name charset` from the supported list, so locale.gen is not a shell injection sink given those checks.

The last-administrator check counts `sudo` group members via `getgrnam`, not users whose primary group is `sudo`, and not members of other admin groups. The UI count uses the same group. A sole admin whose membership is only a primary group id can be demoted.

**Fix:** Require the account to be listed in `/etc/passwd` (`fgetpwent` on that file) before `userdel` or `chpasswd`. Count admin status from the group file and from primary gid. Keep the existing string checks.

### F17. Medium. A removed user's home is parked on tmpfs when the rename works

`src/privileged/lcos-settings-priv.cpp:508`, `src/privileged/lcos-settings-priv.cpp:789`

When `/home/<name>` and `/run` are the same filesystem, the home directory is renamed into the undo token directory. Commit then `rm -rf`s that directory. A crash, kill, or reboot before OK or Cancel drops the only copy, because `/run` is tmpfs. The dialog tells the user Cancel will restore the files. See F7 for the `EXDEV` case, which is the one LCOS will usually hit.

**Fix:** Do not move the home directory into `/run`. Leave it in place, `userdel` without `-r`, and on commit either leave the directory (and say so) or remove it with a confirmed, same-filesystem operation after the account is gone. On revert, `useradd` back onto the existing directory.

### F22. Medium. The inactivity label wraps in the middle of the sentence, and the real minimum is 760×520
